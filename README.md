# Global Music Dynamics

Interactive dashboard visualizing foreign music flows across Spotify's national Top 200 charts: which countries export their music internationally, which import it, and how strongly they're connected. Built with two interchangeable views: a force-directed network graph and a 3D globe.

## Features

- **Network view** — force-directed graph (Cytoscape + cola layout) of countries as nodes, sized by network involvement and colored by import/export dominance. Click a node to see its top trading partners; hover a node to preview its name via a floating tooltip.
- **Map view** — 3D globe (react-globe.gl) rendering the same data on real country geometry. Click a country to zoom in, then pull back to reveal its top 5 import/export partners as animated arcs.
- **Search, threshold filter, and top-5-only toggle** to control which relationships are visible.
- **Detail panel** showing local vs. foreign chart composition, export/import intensity, and ranked trading partners for the selected country.
- **Languages** - supports English and French languages.

## Tech stack

- React 19 + Vite
- [Cytoscape.js](https://js.cytoscape.org/) + `cytoscape-cola` for the network layout
- [react-globe.gl](https://github.com/vasturiano/react-globe.gl) + `d3-geo` + `topojson-client` for the 3D globe
- `world-atlas` for country geometry (TopoJSON, ISO 3166-1 numeric-keyed)

## Data

The app expects `public/data/network.json`, shaped as:

```json
{
  "metadata": { "title": "...", "n_countries": 0, "n_edges": 0 },
  "countries": [
    {
      "id": "ID",
      "name": "COUNTRY NAME",
      "local_share": 0.1234,
      "foreign_share": 0.5678,
      "unknown_share": 0.9123,
      "export_intensity": 0.0,
      "import_intensity": 1.4567,
      "net_dominance": -1.0,
      "network_involvement": 1.8910,
      "n_weeks": 52
    }
  ],
  "edges": [
    { "source": "ID", "target": "ID", "weight": 0.05, "n_weeks": 40 }
  ]
}
```

It's generated by a Python export function (`export_network_data`) from chart/network dataframes. If the file is missing, the app falls back to a demo/empty state and shows a notice in the UI.

### Country names

The country names are fetched through [`pycountry`](https://pypi.org/project/pycountry/) (`pip install pycountry`, no network calls, static ISO dataset) with a small `NAME_OVERRIDES` dict reserved only for deliberate style choices (e.g. "South Korea" over pycountry's "Korea, Republic of", "Türkiye"). `network.json` is regenerated this way.

> Note: non-standard codes (e.g. Kosovo, `xk`) aren't in the official ISO 3166-1 list and won't resolve via `pycountry` — keep those in `NAME_OVERRIDES` explicitly if your dataset includes them.


## Deployment (Vercel / Netlify)

This is a static Vite build — no backend, no environment variables required so far (no API keys, no auth; `network.json` is static data served from `public/`).

- **Build command:** `npm run build`
- **Output directory:** `dist`
- Both platforms auto-detect Vite projects; no custom config needed to deploy.

If you later add anything that needs a secret (e.g. a live Spotify API key), use a `.env` file with `VITE_`-prefixed variables — but remember Vite inlines `VITE_*` variables into the client bundle, so only put things there that are safe to be public. Never commit `.env` (see `.gitignore` below).
