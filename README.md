# Global Music Dominance

Interactive dashboard visualizing foreign music flows across Spotify's national Top 200 charts — which countries export their music internationally, which import it, and how strongly they're connected. Built with two interchangeable views: a force-directed network graph and a 3D globe.

## Features

- **Network view** — force-directed graph (Cytoscape + cola layout) of countries as nodes, sized by network involvement and colored by import/export dominance. Click a node to see its top trading partners; hover a node to preview its name via a floating tooltip.
- **Map view** — 3D globe (react-globe.gl) rendering the same data on real country geometry. Click a country to zoom in, then pull back to reveal its top 5 import/export partners as animated arcs.
- **Search, threshold filter, and top-5-only toggle** to control which relationships are visible.
- **Detail panel** showing local vs. foreign chart composition, export/import intensity, and ranked trading partners for the selected country.

## Tech stack

- React 19 + Vite
- [Cytoscape.js](https://js.cytoscape.org/) + `cytoscape-cola` for the network layout
- [react-globe.gl](https://github.com/vasturiano/react-globe.gl) + `d3-geo` + `topojson-client` for the 3D globe
- `world-atlas` for country geometry (TopoJSON, ISO 3166-1 numeric-keyed)

## Data

The app expects `public/data/network.json`, shaped as:

```json
{
  "metadata": { "title": "...", "n_countries": 0, "n_edges": 0 },
  "countries": [
    {
      "id": "ae",
      "name": "United Arab Emirates",
      "local_share": 0.0003,
      "foreign_share": 0.9997,
      "unknown_share": 0.1245,
      "export_intensity": 0.0,
      "import_intensity": 1.0764,
      "net_dominance": -1.0,
      "network_involvement": 1.0764,
      "n_weeks": 53
    }
  ],
  "edges": [
    { "source": "us", "target": "ae", "weight": 0.05, "n_weeks": 40 }
  ]
}
```

It's generated by a Python export function (`export_network_data`) from chart/network dataframes. If the file is missing, the app falls back to a demo/empty state and shows a notice in the UI.

### Country names — use `pycountry`, not a hand-written dict

The export script originally used a small hardcoded `{code: name}` dict covering ~46 countries, falling back to `code.upper()` for anything else. That silently wrote codes like `"BG"` or `"HN"` into the `name` field for every country outside that list (all of Central America, Bulgaria, etc.) — and because the value was non-empty, no frontend fallback could tell it apart from a real name.

Fixed by resolving names through [`pycountry`](https://pypi.org/project/pycountry/) (`pip install pycountry`, no network calls, static ISO dataset) with a small `NAME_OVERRIDES` dict reserved only for deliberate style choices (e.g. "South Korea" over pycountry's "Korea, Republic of", "Türkiye"). Once `network.json` is regenerated this way, `name` is reliable and the frontend can use it directly — no `Intl.DisplayNames` or lookup workaround needed on the client.

> Note: non-standard codes (e.g. Kosovo, `xk`) aren't in the official ISO 3166-1 list and won't resolve via `pycountry` — keep those in `NAME_OVERRIDES` explicitly if your dataset includes them.

## Deployment (Vercel / Netlify)

This is a static Vite build — no backend, no environment variables required today (no API keys, no auth; `network.json` is static data served from `public/`).

- **Build command:** `npm run build`
- **Output directory:** `dist`
- Both platforms auto-detect Vite projects; no custom config needed to deploy.

If you later add anything that needs a secret (e.g. a live Spotify API key), use a `.env` file with `VITE_`-prefixed variables — but remember Vite inlines `VITE_*` variables into the client bundle, so only put things there that are safe to be public. Never commit `.env` (see `.gitignore` below).

## Known fixes applied in this pass

1. **Country naming bug** — `MapView.jsx` had a dangling reference to an undefined `countryNames` variable in its globe-label fallback, and both the globe tooltip and network detail panel trusted `network.json`'s `name` field blindly. Root cause was the Python export's incomplete hardcoded name dict (see above); fixed at the source with `pycountry`, and the dead `countryNames.of(a2)` reference was removed from `MapView.jsx`.
2. **Network view hover** — added a floating tooltip (mirroring the globe's hover behavior) showing a country's full name on node hover, positioned via Cytoscape's `renderedPosition()`.
3. **Layout regression from the tooltip change** — wrapping the Cytoscape container in an extra `<div>` broke the existing `flex: 1` sizing inherited from `.network-card`'s flex layout, collapsing the graph to zero height. Fixed by keeping `.network` as the sized flex child and absolutely positioning the Cytoscape container and tooltip inside it, instead of introducing a second flex layer.
